# 设计说明：为什么选择「隐藏端点」而不是「切换默认设备」

> 本文回答一个核心设计问题，并说明本项目**当前实现的是「只隐藏端点」**这一种动作。

---

## 1. 两种做法的本质区别

| | **隐藏端点**（本项目采用） | **切换默认设备** |
|---|---|---|
| 改的东西 | 端点的**系统级可见性**（HKLM） | 默认播放/录音设备的**用户选择**（HKCU） |
| 生效范围 | **全系统、所有用户** | **仅当前用户** |
| 用的接口 | `IPolicyConfig::SetEndpointVisibility`（未公开） | `IPolicyConfig::SetDefaultEndpoint`（未公开） |
| 效果 | 设备从「可用列表」**消失**，应用无法再选到它 | 设备仍在列表里，只是**不再自动被选中** |
| 典型用途 | 让「本来不该出现」的端点不再出现 | 避免声音被自动路由到某个设备 |

**关键点**：G3 Max 的端点**永远 `ACTIVE`**，所以「切换默认设备」只能改变**路由**，
并不能阻止它出现在列表里、也不能阻止应用/Windows 在其它时机把它选回去。要做到
「耳机没开就等于这台设备不存在」，只有**隐藏端点**这一条路。

---

## 2. 为什么隐藏是安全的（以及风险在哪里）

- `SetEndpointVisibility` 正是 **Windows「设置 → 声音 → 更多声音设置」里
  「禁用/启用设备」按钮**内部调用的接口，普通用户权限即可；
- 它写的是 **HKLM 系统级 PnP 音频策略键**，所以**不需要管理员**，但也意味着
  **对所有用户生效**——这是它唯一的“重”之处；
- 本项目用**多重保险**把它约束在安全范围内：
  1. **空集合 = 失败**（绝不“假成功”）；
  2. 只操作**识别出的本耳机端点**，绝不碰其它设备；
  3. 每次操作后用 `IMMDeviceEnumerator` + `IAudioEndpointVolume` **独立复核**；
  4. 复核不过 → **回滚为「可用」**（宁可多显示，不可让设备消失）；
  5. 连续失败 → **熔断**，转只观察；
  6. 启动时**自愈**：先把可能卡住的端点恢复为可用，再由判定决定去留；
  7. `--monitor` 只观察模式。

---

## 3. 其它可选方案（以及为什么没选）

| 方案 | 说明 | 结论 |
|---|---|---|
| **PnP 禁用**（`Disable-PnpDevice`） | 直接把接收器/端点禁用 | ❌ 需要管理员；且禁用接收器会影响充电/按键，副作用大 |
| **切换默认设备** | 改路由 | ➖ 不能真正让设备消失（见上），**可作为隐藏之外的补充** |
| **音量归零 / 静音** | 把该端点音量设为 0 | ❌ 设备仍存在，仍可能被选中，且用户会困惑 |
| **拦截音频会话** | 会话级重定向 | ❌ 复杂、不稳定、影响其它应用 |
| **卸载/重装驱动** | 强制端点消失 | ❌ 极重，风险高 |
| **只靠事件（`IMMNotificationClient`）** | 监听设备变化 | ❌ 端点**不会**变化，事件永不触发（这正是问题根源） |

---

## 4. 推荐的完整形态（可选增强）

如果将来希望把体验再推进一步，可以在**保留隐藏为核心**的前提下叠加**可选的
默认设备切换**，做成可配置的动作模型：

```json
{ "action": "both" }   // hide | switch | both（默认 both）
```

- `hide`：只隐藏端点（**本项目当前形态**）；
- `switch`：只切默认设备；
- `both`：先隐藏，再（必要时）把默认设备让给用户偏好的设备。

配套需要：记录并**只还原自己改过**的默认设备、人为切换后的**宽限期**、
以及沿用现有的全部安全机制。此增强**尚未实现**，仅在本文记录设计取舍。

---

## 5. 结论

- **核心动作 = 隐藏端点**：只有它能让“耳机没开”真正等价于“设备不存在”；
- **切换默认设备只能作为补充**，不能替代隐藏；
- 当前版本**只实现隐藏**，追求的是**简单、可验证、最安全**。
